## Qué es y para qué sirve

Ya usaste `serial` en lecciones anteriores de este mismo temario — es la forma más antigua de tener un id autoincremental en Postgres, y en realidad es "azúcar sintáctico": crea una secuencia (próxima lección) y la conecta a la columna con un `DEFAULT`. Desde la versión 10, Postgres tiene una alternativa más moderna y más alineada con el estándar SQL: las **columnas identity**, con `GENERATED ALWAYS AS IDENTITY`.

```laboratorio

  "despues": "<script>\n-- GENERATED ALWAYS AS IDENTITY: Postgres controla el valor de verdad\nCREATE TABLE pedidos (\n  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,\n  total numeric\n);\nINSERT INTO pedidos (id, total) VALUES (999, 50);\n-- ERROR: cannot insert a non-DEFAULT value into column \"id\"\n-- DETAIL: Column \"id\" is an identity column defined as GENERATED ALWAYS.\n</script>",
  "nota": "Con GENERATED ALWAYS (a diferencia de GENERATED BY DEFAULT, que sí permite el mismo hueco que serial), Postgres rechaza cualquier INSERT que intente fijar el id a mano — evita por completo la categoría de bug de \"alguien puso un id manual y ahora hay un choque con el autoincremental\"."
}
```
