## RLS / GRANT (`0005_icons.sql`)

```sql
alter table public.categories add column icon text check (...);
alter table public.technologies add column icon text check (...);
grant insert (icon), update (icon) on table public.categories to authenticated;
grant insert (icon), update (icon) on table public.technologies to authenticated;
```

Sin políticas nuevas ni modificadas — las políticas owner-admin ya
existentes de `categories`/`technologies` (`0003_public_docs.sql`)
cubren automáticamente cualquier columna de la fila, incluida esta.
Los `GRANT` solo amplían por columna, mismo patrón que `0004`. `icon`
no estaba concedido antes de esta migración, así que sin ella
`insert`/`update` con ese campo se habría rechazado, no ignorado en
silencio.

## Inyección / XSS

`icon` nunca se renderiza como texto ni HTML — solo se usa como *key*
de lookup en un mapa fijo en código
(`categoryIcons[row.icon ?? '']?.Icon ?? CircleHelp`,
`technologyIcons[...]`). Un valor que no exista en el mapa (por typo,
dato corrupto, o un `PATCH` directo a la API saltándose el picker)
simplemente no encuentra entrada y cae al icono `CircleHelp` por
defecto — no hay manera de que un valor de `icon` controlado por un
atacante llegue al DOM como contenido. El picker (`IconPicker`) es
además un conjunto cerrado — no hay `<input type="text">` libre para
este campo en el formulario — y el `refine` de Zod
(`key in categoryIcons`/`technologyIcons`) ya rechaza en cliente
cualquier valor fuera de la lista antes de intentar el submit.
